## 3. WHAT WENT WRONG (DO NOT REPEAT THESE MISTAKES)

This section exists explicitly to stop future agents from wasting hours.

### ❌ Mistake 1: Using Proxmox API modules for LXC creation

* `community.general.proxmox` and `community.proxmox.proxmox` **caused repeated token failures**
* Tokens were valid (verified via curl), but Ansible modules:

  * mangled token IDs
  * double-prefixed users (`ansible@pve!ansible@pve`)
  * behaved inconsistently across versions

**Conclusion:**
➡️ **DO NOT** use Proxmox API modules for provisioning LXCs in this environment.

---

### ❌ Mistake 2: Assuming template filenames are stable

* Debian 12 template names vary by Proxmox version
* Hardcoding `debian-12-standard_12.x-x_amd64.tar.zst` breaks

**Correct approach:**

* Discover template dynamically via `pveam list local`
* Normalize output
* Build `local:vztmpl/<filename>` exactly once

---

### ❌ Mistake 3: Assuming SSH keys exist on the Proxmox host

* `pct create --ssh-public-keys ~/.ssh/id_ed25519.pub` failed
* That file existed on the **Ansible control machine**, not Proxmox

**Correct approach:**

* Copy the public key from Ansible → Proxmox (`ansible.builtin.copy`)
* Reference a known path (e.g. `/root/ansible_pubkey.pub`)

---

### ❌ Mistake 4: Overengineering early

* Regex patching YAML
* Complex token abstractions
* Trying to “future-proof” before first container existed

**Lesson:**
➡️ Make **CT110 exist first**, cleanly, deterministically.

## 4. FINAL, WORKING PROVISIONING MODEL (THIS IS THE BASELINE)

### 4.1 Provisioning Method (LOCKED IN)

* **SSH-based provisioning**
* Ansible executes:

  * `pveam`
  * `pct`
* Runs **on the Proxmox host**
* Requires:

  * SSH access as `root`
  * No Proxmox API tokens

This is:

* Idempotent
* Fast
* Version-agnostic
* Proven working
