# Usniverse – Handover 3 (2026‑01‑21)

## Purpose
This document is a **full, end‑to‑end handover** of the current state of the Usniverse homelab after a major migration.

It is written so that a **new agent can pick up immediately**, understand *why things are the way they are*, and avoid repeating the mistakes already encountered.

---

## High‑level architecture (current)

### Proxmox
- Single Proxmox host (`pve`)
- All services run in **unprivileged LXCs**
- Backups use `vzdump` to **NFS storage (Global_Share)**

### Edge & ingress
- **CT110 – edge‑proxy**
  - Role: *single ingress point*
  - Runs **Tailscale**
  - Owns **iptables DNAT** for all public services
  - Replaces `UbuntuVM2` completely

### Tailscale
- **Edge‑proxy (CT110)** now owns the stable Tailscale IP
- UbuntuVM2 Tailscale has been **stopped / deprecated**
- All external access goes via:
  - `100.122.95.117` (edge‑proxy TS IP)

## Ansible structure (important)

### Playbooks
- `playbooks/lxc_ssh.yml`
  - Creates LXCs via `pct`
  - Injects SSH keys
  - Must run **against `pve` only**

- `playbooks/base_lxc.yml`
  - Baseline config for LXCs
  - Installs Docker, Python, sudo, etc

### Roles
- `roles/base_lxc`
  - Needs **rsync added** to `base_lxc_packages` (missing earlier)

### Critical rule
> **Do NOT put ProxyJump for `pve` through itself**

- `pve` must be reachable **directly via its Tailscale IP**
- ProxyJump is only for **LXCs**

## SSH & connectivity rules

### From workstation (`rog_ubuntu`)
- Direct SSH to:
  - `pve`
  - `ct110`

- All other LXCs are reached:
  - via Ansible inventory + SSH keys
  - **not** via UbuntuVM2

### Known issue avoided
- SSH loops occurred when:
  - `ansible_ssh_common_args` chained `pve → pve`

## Ombi (CT118) – IMPORTANT

### Container
- Image: `lscr.io/linuxserver/ombi:latest`
- Port: `3579`
- Volume: `/opt/ombi/config → /config`

### Current symptom
- Ombi UI loads
- **Login fails**

### Root cause
- **Config DBs were recreated**, not fully restored
- New file detected:
  - `OmbiSettings.db` (timestamp newer than others)

### Required fix (not yet done)

1. Stop Ombi on CT118
2. Copy **entire config directory** from old host:
   - `Ombi.db`
   - `OmbiSettings.db`
   - `OmbiExternal.db`
   - `.aspnet/DataProtection-Keys`
3. Ensure ownership:
   - UID/GID = `1000:1000`
4. Restart Ombi

Until this is done:
- **Login will never succeed**
